01

Массивы

Массив в Go — контейнер фиксированного размера, хранящий элементы одного типа. В памяти это последовательная область ячеек, в которых лежат значения.

Размер массива задаётся при объявлении и становится частью типа. Массивы разной длины — это разные типы: массив сам по себе сравниваемый (к нему применимы == и !=), но сравнить между собой массивы разной длины не получится:

main.gogo
var numbers3 [3]int  // Массив из трёх целых чисел
var numbers5 [5]int  // Массив из пяти целых чисел

numbers3 == numbers5 // Ошибка компиляции: разные типы

По той же причине массив одной длины нельзя привести к типу массива другой длины, а длина не может быть переменной — раз она часть типа, компилятор обязан знать её на этапе компиляции.

При объявлении через var массив заполняется zero value своего типа — ровно столько раз, сколько указано в квадратных скобках:

main.gogo
var temperatures [7]float64  // Семь температур на неделю
var scores [5]string         // Пять оценок студента

fmt.Println(temperatures)   // [0 0 0 0 0 0 0] — нулевые значения для float64
fmt.Println(scores)         // ["" "" "" "" ""] — нулевые значения для string

Есть и другие способы: инициализировать все значения сразу, частично, либо создать разреженный массив, назначив значения по конкретным индексам:

main.gogo
// Все значения сразу
weekdays := [7]string{
	"Понедельник", "Вторник", "Среда", "Четверг",
	"Пятница", "Суббота", "Воскресенье",
}

// Частичная инициализация
grades := [5]int{95, 87, 92} // [95 87 92 0 0] — остальные нули

// Разреженный массив
scores := [4]int{1, 2: 14} // [1 0 14 0] — по индексу 2 (с нуля) стоит 14

Длину можно и не указывать вовсе — тогда вместо числа ставится троеточие, и компилятор сам вычисляет длину массива по количеству элементов:

main.gogo
months := [...]string{
	"Январь", "Февраль", "Март", "Апрель",
	"Май", "Июнь", "Июль", "Август",
	"Сентябрь", "Октябрь", "Ноябрь", "Декабрь",
}

Длина и ёмкость массива

  • len — возвращает длину: количество элементов, которые тип реально в себе содержит;
  • cap — возвращает ёмкость: максимум элементов, под которые уже выделена память.

У массива по его природе всегда len(x) == cap(x):

main.gogo
cities := [5]string{"Москва", "Долгопрудный"}
fmt.Println(len(cities)) // 5
fmt.Println(cap(cities)) // 5

Работа с массивом

Массивы разных типов не взаимодействуют, но значения между массивами одного типа копируются — и переменные становятся полностью независимыми друг от друга:

main.gogo
a := [3]int{1, 2, 3}
b := a
b[0] = 99
fmt.Println(a) // [1 2 3]
fmt.Println(b) // [99 2 3]

Доступ к отдельным значениям — через индексы, порядковые номера с отсчётом от 0:

main.gogo
cities := [3]string{"Москва", "СПб", "Казань"}

fmt.Println("Первый город:", cities[0]) // Москва
fmt.Println("Второй город:", cities[1]) // СПб
fmt.Println("Третий город:", cities[2]) // Казань

cities[1] = "Санкт-Петербург"
fmt.Println(cities) // [Москва Санкт-Петербург Казань]
// runtime panic

Индекс за пределами длины массива — гарантированная паника:

fmt.Println(cities[5]) // panic: runtime error: index out of range [5] with length 3

Массив — составной тип, поэтому по нему можно пройтись циклом. Классический вариант — счётчик от 0 до len(x)-1 (почему нумерация должна начинаться с нуля):

main.gogo
prices := [4]float64{19.99, 25.50, 12.30, 45.00}

for i := 0; i < len(prices); i++ {
	fmt.Printf("Товар %d стоит %.2f руб.\n", i+1, prices[i])
}

Опасность этого способа — легко указать неверную границу и словить ошибку в рантайме. Более идиоматичный путь — for-range:

main.gogo
fruits := [4]string{"яблоко", "банан", "апельсин", "груша"}

// С индексом и значением
for index, fruit := range fruits {
	fmt.Printf("%d. %s\n", index+1, fruit)
}

// Только значения
for _, fruit := range fruits {
	fmt.Println("Фрукт:", fruit)
}

// Только индексы
for index := range fruits {
	fmt.Printf("Индекс %d\n", index)
}
// осторожно

_ — пустой идентификатор, говорящий компилятору игнорировать значение. Переменные цикла — это копии значений массива: их изменение не затронет сам массив. Чтобы изменить массив, всегда обращайся по индексу.

Ограничения массивов

  • Фиксированный размер — изменить его после объявления нельзя;
  • Размер — часть типа — [10]int и [20]int несовместимы;
  • Копирование при передаче — дорого для больших массивов.
main.gogo
func processNumbers(numbers [100]int) { // Что, если нужно 200 чисел?
	// Обработка 100 чисел
}

func processMoreNumbers(numbers [200]int) { // Другая функция!
	// Обработка 200 чисел
}
// Нужны две разные функции для разных размеров массивов!

Именно поэтому массивы в Go редко применяются в чистом виде — их место занимают слайсы.

02

Слайсы: гибкая альтернатива массивам

На первый взгляд слайсы (срезы) очень похожи на массивы: создаются почти так же, обращение по индексу такое же, итерируются одинаково, а выход за границы так же приводит к ошибке. Но за этим сходством прячутся четыре серьёзных отличия.

flowchart LR
  subgraph SL["Слайс — это структура"]
    direction TB
    P["array → указатель"]
    L["len → длина"]
    C["cap → ёмкость"]
  end
  SL -- "указывает на" --> ARR["Базовый массив в памяти
[ x | x | x | x | x | x ]"]

Слайс не хранит данные сам — он лишь указатель + длина + ёмкость поверх настоящего массива

№1

Динамический размер. Слайс не имеет длины как части типа и объявляется без числа в скобках. Необъявленный слайс не инициализирован — его значение nil, память под него не выделена.

№2

Надстройка над массивом. Под капотом слайс — структура из указателя на первый элемент, длины и ёмкости. Сами данные лежат в базовом массиве, на который слайс лишь ссылается.

№3

Несравниваемый тип. В отличие от массива, слайс нельзя сравнить с чем-либо через == и !=.

№4

Реслайс. Массив остаётся массивом, а срез можно взять и от массива, и от другого слайса — не создавая новый базовый массив, а лишь переопределяя, что именно считать базовым массивом.

Пустой слайс с реальной (но пустой) инициализацией создаётся так:

main.gogo
var numbers []int  // nil-слайс, память не выделена
var names []string

empty := []int{}   // реально пустой, но инициализированный слайс

Для слайсов появляется идиоматичный способ создания — встроенная функция make. Она принимает тип, длину и (опционально) ёмкость:

main.gogo
// make([]T, length) — слайс заданной длины
numbers := make([]int, 5) // [0 0 0 0 0], len=5, cap=5

// make([]T, length, capacity) — длина + резерв ёмкости
buffer := make([]int, 0, 10) // [], len=0, cap=10

fmt.Printf("numbers: len=%d, cap=%d, %v\n", len(numbers), cap(numbers), numbers)
// numbers: len=5, cap=5, [0 0 0 0 0]
fmt.Printf("buffer: len=%d, cap=%d, %v\n", len(buffer), cap(buffer), buffer)
// buffer: len=0, cap=10, []

Для слайса len и cap работают иначе, чем для массива: len — сколько элементов реально заполнено, cap — сколько всего зарезервировано (заполненные + свободные).

Раз слайс динамический, его можно наращивать через встроенную функцию append. Первый аргумент — исходный слайс, дальше — произвольное количество добавляемых элементов:

main.gogo
var shopping []string
fmt.Println("Список покупок:", shopping) // []

shopping = append(shopping, "хлеб")
fmt.Println("Добавили хлеб:", shopping) // [хлеб]

shopping = append(shopping, "молоко", "яйца")
fmt.Println("Добавили еще:", shopping) // [хлеб молоко яйца]
// частая ошибка

append возвращает новый слайс — результат обязательно нужно присваивать обратно той же переменной.

flowchart TD
  A["append(slice, x)"] --> B{"len == cap ?"}
  B -- "нет, есть место" --> C["дописываем элемент

  B -- "да, места нет" --> D["выделяем новый

Ровно поэтому результат append нужно переприсваивать: слайс может «переехать» в новую область памяти

На сколько именно слайс растёт во втором случае — решает growSlice в рантайме (исходник на GitHub): он выделяет с запасом, чтобы не дёргать аллокатор на каждый чих. Конкретное новое значение ёмкости подбирает nextslicecap (исходник). Алгоритм меняется от версии к версии — знать о нём стоит, но полагаться на конкретные цифры не стоит.

// под капотом

Упрощённая структура слайса в рантайме Go (исходник):

type slice struct {
	array unsafe.Pointer // Указатель на первый элемент
	len   int            // Длина
	cap   int            // Ёмкость
}

Когда элементов становится больше cap, создаётся новый массив в новой области памяти, данные переносятся туда, а старый массив удаляется.

Взять срез можно и от массива, и от слайса — процесс называется реслайсом. В примере ниже первым элементом специально добавлена пустая строка, чтобы индекс совпадал с порядковым номером месяца:

main.gogo
months := [12 + 1]string{
	"", "January", "February", "March", "April", "May", "June",
	"July", "August", "September", "October", "November", "December",
}

var (
	allMonths  = months[:]       // Все элементы
	firstHalf  = months[1 : 6+1] // Первые 6 месяцев
	secondHalf = months[7:]      // Последние 6 месяцев
	summer     = months[6 : 8+1] // Июнь, июль, август
)
fmt.Println("Лето:", summer) // [June July August]

Синтаксис [start:end] означает «с индекса start до end, не включая end»; опущенный start — с начала, опущенный end — до конца. Все эти слайсы смотрят на один и тот же базовый массив — а значит, делят и часть его элементов.

Есть и расширенный синтаксис [start:end:maxCap], где maxCap ограничивает ёмкость нового базового массива: newCap = maxCap - start. Без maxCap ёмкость считается как len(slice/array) - start.

main.gogo
summer[0] = "ИЮНЬ"                              // Изменяем слайс
fmt.Println("Исходный массив:", months[6])      // ИЮНЬ — массив изменился!
fmt.Println("Первая половина:", firstHalf[6-1]) // ИЮНЬ — и тут изменилось!
// ссылочная семантика

Изменение элемента через один слайс видно во всех остальных слайсах на тот же базовый массив: слайс лишь указывает на данные, а не копирует их. Здесь же наглядно видно, что такое cap — это длина от первого элемента слайса до конца базового массива.

Ещё важное о слайсах

Чтобы получить по-настоящему независимую копию, есть встроенная функция copy — не нужно вручную гонять цикл:

main.gogo
func copyExample() {
	original := []string{"a", "b", "c", "d", "e"}

	destination := make([]string, len(original))
	n := copy(destination, original)
	fmt.Printf("Скопировано %d элементов\n", n) // 5

	destination[0] = "MODIFIED"

	fmt.Println("Оригинал:", original)    // [a b c d e]
	fmt.Println("Копия:   ", destination) // [MODIFIED b c d e]
}

copy безопасно копирует min(len(src), len(dst)) элементов — ровно столько, сколько влезет в приёмник.

Функции удаления элемента в Go нет — но её легко собрать через «склейку» частей слайса с помощью append:

main.gogo
func removeElement(slice []string, index int) []string {
	// Объединяем части до и после удаляемого элемента
	return append(slice[:index], slice[index+1:]...)
}

func main() {
	fruits := []string{"яблоко", "банан", "апельсин", "груша", "киви"}
	fruits = removeElement(fruits, 2) // удаляем "апельсин"
	fmt.Println("После удаления:", fruits) // [яблоко банан груша киви]
}
slice[:index]
все элементы до удаляемого, не включая его.
slice[index+1:]
все элементы после удаляемого.
append(...)
склеивает эти две части в одну.

Оператор ... распаковывает слайс в вариадический параметр — «раскрывает» его для рантайма поэлементно. Многое из необходимого для слайсов уже есть в пакете стандартной библиотеки slices (исходник на GitHub) — стоит изучить его самостоятельно.

Немного о nil

nil — специальное нулевое значение для ссылочных типов: «ничего», «пустой указатель», «несуществующее значение». Мы вернёмся к этой концепции подробнее, когда доберёмся до указателей и интерфейсов. Слайс со значением nil имеет len и cap, равные 0, и его тоже можно передавать в append.

03

Мапы: встроенные хеш-таблицы

Мапа — ещё один встроенный составной тип для хранения ассоциативных данных «ключ — значение», где оба могут быть разных типов. Единственное ограничение: ключи обязаны быть сравниваемыми.

main.gogo
var m map[int]string
// важно

Такая мапа объявлена, но не инициализирована — её значение nil, и попытка записи в неё завершится ошибкой.

Сравниваемые типы

Сравниваемые переменные можно сопоставлять через == и !=, если сравниваемы их типы. Из уже известных нам типов сравниваемы (и годятся в ключи мапы):

boolstring int / int8 / int16 / int32 / int64 uint / uint8 / uint16 / uint32 / uint64 / uintptr float32 / float64 complex64 / complex128 массивы

Несравниваемы: слайсы и мапы. К обеим группам мы ещё вернёмся по ходу курса.

Работа с мапами

Инициализировать мапу можно двумя способами: через make (пустую или сразу с резервом ёмкости) либо заполнив её значениями прямо при объявлении:

main.gogo
m1 := make(map[int]bool)     // Пустая инициализированная мапа
m2 := make(map[bool]int, 10) // С резервом на 10 значений
m3 := map[float32]bool{1.2: true, 1.5: false} // С фактическими значениями

Чтение и запись — обращением по ключу, удаление — через delete. А что если нужно узнать, есть ли ключ вообще? Запрос несуществующего ключа тихо вернёт zero value — поэтому для проверки существует нотация value-ok:

main.gogo
m := make(map[int]bool)
m[1] = true       // Запись
fmt.Println(m[1]) // Чтение: true
delete(m, 1)      // Удаление

v, ok := m[2] // v всегда что-то содержит: zero value или реальное значение
if !ok {
	fmt.Println("ключа нет!") // ключа правда нет — выведется
}

var m1 map[int]int
fmt.Println(len(m1), len(m)) // 0 0 — неинициализированная (nil) мапа тоже имеет длину 0
// хорошая практика

Проверяй мапу не на nil, а на длину через len(). cap() для мапы не существует.

При обходе мапы циклом порядок пар недетерминирован — каждый раз рандомный. Исключение — вывод через fmt.Println: внутри реализована сортировка ключей, поэтому результат всегда стабилен. Проверь сам!

main.gogo
for k, v := range m { // k — ключ, v — значение. Порядок случайный
	fmt.Println(k, v)
}
fmt.Println(m) // Всегда один и тот же порядок вывода

Внутреннее устройство

Мапам повезло стать живой иллюстрацией эволюции языка: в версии 1.24 их внутреннее устройство сменилось впервые за долгое время. Верхнеуровневый ответ «мапа — это хеш-таблица с хеш-функцией» остаётся верным в обеих версиях; отличается то, что происходит дальше. Сама мапа как была структурой (как и слайс), так и осталась. В исходниках теперь два места — новая реализация и старая — их стоит изучить отдельно, здесь только суть:

ХарактеристикаДо Go 1.24После Go 1.24 (Swiss Table)
ПринципБакеты + overflow-цепочки через указателиОткрытая адресация, один непрерывный массив памяти
Размер группы8 слотов в бакете, доп. overflow-бакеты по мере надобности8 слотов в группе, без цепочек указателей
Быстрый отсев1 байт tophash (старшие биты хеша)7-бит h2 в 64-битном контрольном слове — сразу для 8 слотов, через SIMD
Коэффициент загрузки~81%~87,5%
Рост таблицыУдвоение размера, перенос бакетов инкрементальноСегментированный рост по подтаблицам ~1000 элементов
Защита от hash-floodingСлучайный seed при создании мапыСохраняется

До 1.24: индекс бакета вычислялся побитовым маскированием (число бакетов всегда степень двойки — без операции взятия остатка), а при достижении порога загрузки или слишком длинных overflow-цепочек запускался рост таблицы. После 1.24: контрольное слово даёт сравнение восьми слотов за одну операцию (на платформах без SIMD — через оптимизированный побайтовый цикл), что снижает число дорогих сравнений ключей. Причина именно такой конструкции — кэш-линии процессора: блоки фиксированного размера, в которые данные стоит укладывать целиком ради скорости доступа.

Последнее о мапах

Как и у строк со слайсами, у мап есть собственный пакет стандартной библиотеки — maps (исходник на GitHub). Стоит изучить его, чтобы быть во всеоружии.

04

Указатели

Указатели и ссылки на первый взгляд кажутся синонимами. Это не так: указатель — переменная, которая хранит адрес в памяти другой переменной; ссылка — псевдоним существующего объекта, который нельзя инициализировать как null/nil. В Go ссылок не существует — только указатели.

Зачем нужны указатели

  • Эффективность — не копировать большие структуры данных
  • Изменение значений — менять переменные прямо внутри функций
  • Работа с nil — представление отсутствующего значения
  • Разделяемое состояние — несколько переменных ссылаются на одни данные

Два оператора

  • & — взятие адреса: получить адрес в памяти, где лежит значение
  • * — разыменование: получить значение, хранящееся по адресу

Указатель — это просто адрес; *p = 100 меняет x, потому что p и x — одна и та же ячейка памяти

main.gogo
package main

import "fmt"

func main() {
	x := 42
	p := &x // p — указатель на x, хранит адрес x

	fmt.Println("Значение x:", x)   // 42
	fmt.Println("Адрес x:", &x)     // 0xc000012078 (пример)
	fmt.Println("Значение p:", p)   // 0xc000012078 (тот же адрес)
	fmt.Println("Значение *p:", *p) // 42 (разыменование)

	*p = 100 // Изменяем значение через указатель
	fmt.Println("Новое значение x:", x) // 100

	var pi *int    // Указатель на int
	var ps *string // Указатель на string
	var pb *bool   // Указатель на bool

	fmt.Println(pi == nil) // true
}

Нулевое значение указателя по умолчанию — nil.

Как ещё создать указатель

Встроенная функция new выделяет память под значение типа T, инициализирует его нулевым значением и возвращает указатель *T:

main.gogo
p := new(int)
fmt.Println(*p) // 0

*p = 42
fmt.Println(*p) // 42
// не путать

new работает с любым типом. Это не то же самое, что make, которая с указателями не работает вовсе и применима лишь к трём типам: слайсам, мапам и ещё одному, с которым мы познакомимся позже.

05

Неявные указатели

Некоторые типы Go содержат указатель внутри себя, даже когда это не видно из синтаксиса. Их неформально называют ссылочными типами (reference types) — хотя, забавным образом, не «указательными».

В программировании есть две концепции передачи аргументов в функцию: по указателю (передаётся адрес — изменение внутри функции видно и снаружи) и по значению (аргумент копируется, а изменение видно снаружи, только если явно вернуть его через return).

В Go есть несколько ссылочных типов — тебе уже знакомы два: слайс и мапа, они содержат указатель внутри. Массив ссылочным типом не является.

ТипСсылочный?Что реально копируется при передаче
массивнетвсе элементы целиком
слайсдазаголовок: указатель + len + cap
мападауказатель на хеш-таблицу
строканет*указатель на неизменяемые байты (*но сама неизменяема)
main.gogo
func main() {
	m := map[int]int{3: 4}
	sl := make([]int, 1, 2)
	ms := [2]int{1, 2}

	addToMap(m)
	fmt.Println(m) // map[1:2 3:4] — изменения видны вне функции

	addToSlice(sl)
	fmt.Println(sl) // [1] — изменения видны вне функции

	addToMassive(ms)
	fmt.Println(ms) // [1 2] — изменения НЕ видны вне функции
}

func addToMap(m map[int]int) {
	m[1] = 2
}

func addToSlice(m []int) {
	m[0] = 1
}

func addToMassive(m [2]int) {
	m[1] = 3
}

Соблюдай осторожность, передавая слайс или мапу в функцию. Правило хорошего тона — явно возвращать слайс/мапу из функции, если она изменяется. Со слайсом легко напороться на такую ловушку:

main.gogo
func main() {
	sl := make([]int, 1, 2)

	addToSlice(sl)
	fmt.Println(sl) // [1] — изменения НЕ видны: append перезаписал переменную внутри функции
}

func addToSlice(m []int) {
	m[0] = 1
	m = append(m, 2)
	fmt.Println(m) // [1 2] — внутри функции всё корректно
}
// почему так

append перезаписывает переменную m, а её область видимости из-за передачи по значению ограничена телом функции. Чтобы изменение увидел вызывающий код, слайс нужно явно вернуть через return.
