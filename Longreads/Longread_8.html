01

Работа с файлами

Файлы — не только классический текст: CSV, Excel, PDF для фронтенда или админки, изображения, которые порой нужно сжать. Разберём работу с текстовыми файлами — освоив её, с остальными форматами разберёшься по аналогии.

Базовые операции очевидны: открыть, прочитать, записать, создать, проверить существование. За всё отвечает пакет os, а под капотом файл — вот такая обёртка над системным дескриптором:

types.gogo
type File struct {
	*file // os specific
}

Неэкспортируемое поле прячет системную специфику, а наружу торчат только методы экспортируемой структуры. Все они, к слову, конкурентно безопасны.

ФункцияЧто делает
os.Open(name)открывает только для чтения; ошибка PathError, если файла нет
os.OpenFile(name, flag, perm)гибкое открытие — чтение, запись, создание, по флагам
os.Create(name)создаёт файл (или обрезает существующий) для записи
os.ReadFile(name)читает файл целиком в память одним вызовом
os.WriteFile(name, data, perm)пишет данные в файл целиком, создавая его при нужде
os.Stat(name)метаданные о файле — заодно проверка существования

os.Open под капотом сам вызывает os.OpenFile с флагом O_RDONLY:

main.gogo
file, err := os.Open("input.txt")
if err != nil {
	return err
}
defer file.Close()

Не закрыть файл — верный способ получить утечку ресурсов. defer отработает даже при панике. Правильнее закрывать с проверкой ошибки, хоть этим и часто пренебрегают:

main.gogo
defer func() {
	if err := file.Close(); err != nil {
		fmt.Println(err)
	}
}()

Через os.OpenFile файл можно открыть и на чтение, и на запись, и создать заодно — нужны только флаги и права доступа:

main.gogo
file, err := os.OpenFile("notes.txt", os.O_RDWR|os.O_CREATE, 0644)
if err != nil {
	log.Fatal(err)
}

Читать конкретное число байт можно методом Read — не больше, чем вмещает переданный слайс. Дочитал до конца — получишь io.EOF, и это нормальный сигнал, а не поломка:

main.gogo
b := make([]byte, 1024)

for {
	n, err := file.Read(b) // n — сколько байт реально прочитано
	if err != nil {
		if errors.Is(err, io.EOF) {
			return nil
		}
		return fmt.Errorf("Warning: %w", err)
	}
}

Для небольших файлов проще читать целиком через os.ReadFile:

main.gogo
data, err := os.ReadFile("input.txt")
if err != nil {
	log.Fatal(err)
}

fmt.Print(string(data))
// не для гигабайтов

os.ReadFile блокируется до полного чтения и держит весь файл в памяти — для файлов в сотни мегабайт нужен другой подход (раздел ниже).

Проверить, существует ли файл, можно через os.Stat и fs.ErrNotExist:

main.gogo
func fileExists(filename string) (bool, error) {
	_, err := os.Stat(filename)
	if err == nil {
		return true, nil
	}
	if errors.Is(err, fs.ErrNotExist) {
		return false, nil
	}
	return false, err
}

Для записи есть os.WriteFile (создаёт файл при нужде и пишет всё сразу) и методы дескриптора — file.Write() для байтов, file.WriteString() для строк:

main.gogo
err := os.WriteFile("testdata/hello", []byte("Hello, Gophers!"), 0666)
if err != nil {
	log.Fatal(err)
}

Удаление файла оставляем найти самостоятельно — благо, гуглится с полпинка.

02

Пакет io

Пакет io — едва ли не самый чистый пример того, как маленькие интерфейсы дают сильную абстракцию. Загляни в исходник — там почти сплошь интерфейсы:

io.Reader
умеет Read(p []byte) (int, error) — тот самый метод, что мы видели у os.File.
io.Writer
умеет Write(p []byte) (int, error).
io.Closer
умеет Close() error.
io.ReadWriter
Reader + Writer вместе.
io.ReadCloser / io.WriteCloser
Reader/Writer в паре с Closer.
flowchart LR
  R["io.Reader"] --> RW["io.ReadWriter"]
  W["io.Writer"] --> RW
  R --> RC["io.ReadCloser"]
  C["io.Closer"] --> RC
  W --> WC["io.WriteCloser"]
  C --> WC
  RW --> RWC["io.ReadWriteCloser"]
  C --> RWC

Три метода-атома складываются в любую нужную комбинацию поведения — композиция интерфейсов в деле

Взять зависимость на io — значит зависеть только от поведения, а не от конкретной реализации. Даже сами функции пакета принимают на вход эти интерфейсы, а не конкретные типы:

flowchart LR
  SRC["любой io.Reader
файл, сеть, буфер..."] -->|io.Copy| DST["любой io.Writer
файл, сеть, буфер..."]

io.Copy не спрашивает, что именно перед ним — контракт уже описан в типах

io.Copy() копирует данные из любого Reader в любой Writer, вообще не интересуясь их конкретной природой — контракт уже зашит в сигнатуре, а строгая типизация гарантирует, что в проде это точно сработает.

03

Работа с большими файлами

Читать весь файл в память сразу — плохая идея при большом объёме. Ручное чтение через буфер-слайс работает, но легко остановиться на середине слова. Для этого есть готовый инструмент — пакет bufio (buffered input/output).

bufio.Scanner — высокоуровневый инструмент последовательного, чаще всего построчного, чтения:

main.gogo
file, err := os.Open("log.txt")
if err != nil {
	log.Fatal(err)
}
defer file.Close()

scanner := bufio.NewScanner(file)
for scanner.Scan() {
	fmt.Println(scanner.Text())
}

if err := scanner.Err(); err != nil {
	log.Fatalf("Ошибка чтения: %v", err)
}

Конструктору всё равно, что именно в него передали — важно лишь, что параметр удовлетворяет io.Reader. Дальше scanner сам режет поток по токенам (по умолчанию — по \n).

// ограничения Scanner

Буфер ограничен 64 КБ и рассчитан на текст, а не бинарные блоки — полного контроля над чтением он не даёт. scanner.Split(bufio.ScanWords) перед первым Scan() переключает разбиение на пословное вместо построчного — можно читать и по рунам. Для длинных строк, бинарных данных и более серьёзного контроля смотри в сторону bufio.NewReader(io.Reader) — самостоятельно.

Читать можно и не строго последовательно — интерфейс io.Seeker позволяет прыгать на произвольное место в файле:

main.gogo
file.Seek(0, io.SeekStart) // Вернуться к самому началу файла

io.SeekStart задаёт точку отсчёта — в пакете есть ещё пара таких констант.

04

Обход файловой системы

Работа с папками, файлами и путями на диске — базовый навык. За неё отвечают os и path/filepath. Разберём несколько ключевых функций, остальное — самостоятельно.

Создание директорий

main.gogo
err := os.MkdirAll("data/logs", 0755) // Создаст всю цепочку каталогов
if err != nil {
	log.Fatal(err)
}

os.Mkdir создаёт одну директорию; os.MkdirAll — сразу всю недостающую цепочку.

Чтение содержимого директории

main.gogo
entries, err := os.ReadDir("./data")
if err != nil {
	log.Fatal(err)
}

for _, entry := range entries {
	if entry.IsDir() {
		fmt.Println("Каталог:", entry.Name())
	} else {
		fmt.Println("Файл:", entry.Name())
	}
}

Рекурсивный обход

Обходить дерево вручную не нужно — есть готовый рекурсивный обход. filepath.WalkDir предпочтительнее устаревающего filepath.Walk: работает с лёгким DirEntry вместо FileInfo, не открывает файлы без необходимости и экономит системные вызовы.

main.gogo
filepath.WalkDir(".", func(path string, d fs.DirEntry, err error) error {
	if err != nil {
		return err
	}
	if !d.IsDir() {
		fmt.Println(path)
	}
	return nil
})
flowchart TB
  ROOT["."] --> A["cmd/"]
  ROOT --> B["internal/"]
  A --> A1["main.go"]
  B --> B1["config.go"]
  B --> B2["server.go"]
  ROOT -.->|"на каждый узел вызывает"| CB["обработчик обхода(path, d, err)"]

WalkDir рекурсивно обходит дерево и на каждый файл/каталог вызывает твою функцию-обработчик

Обработчик обхода — функция, которая вызывается на каждый элемент дерева; вся пользовательская логика живёт именно в ней.

Аргументы и флаги

Самый простой способ получить аргументы запуска — глобальная переменная os.Args, слайс строк, заполняемый в init() ещё до старта main. Нулевой индекс — не пользовательский аргумент, а путь к самой программе:

main.gogo
func main() {
	fmt.Println("Количество аргументов:", len(os.Args)-1)
	fmt.Println("Название программы:", os.Args[0])

	if len(os.Args) > 1 {
		fmt.Println("Аргументы:")
		for i, arg := range os.Args[1:] {
			fmt.Printf("  %d: %s\n", i+1, arg)
		}
	}
}
терминалbash
go run main.go hello world 123

# Количество аргументов: 3
# Название программы: /tmp/go-build123456/b001/main
# Аргументы:
#   1: hello
#   2: world
#   3: 123
// почему -1

os.Args[0] — всегда путь к бинарнику (при go run — путь к временному файлу), присутствует даже без единого пользовательского аргумента. Сами аргументы начинаются с индекса 1.

Для именованных параметров с типизацией, значениями по умолчанию и авто-справкой — пакет flag. Он сам понимает разные форматы записи (-name=value, -name value, --name value), а булевы флаги можно указывать без значения:

main.gogo
func main() {
	var (
		name    = flag.String("name", "Мир", "имя для приветствия")
		count   = flag.Int("count", 1, "количество повторений")
		verbose = flag.Bool("verbose", false, "подробный вывод")
	)

	flag.Parse() // Вызывать после объявления всех флагов

	if *verbose {
		fmt.Printf("Выполняется приветствие с параметрами: name=%s, count=%d\n", *name, *count)
	}

	for range *count {
		fmt.Printf("Привет, %s!\n", *name)
	}
}
терминалbash
go run main.go -name="Алиса" -count=3 -verbose

# Выполняется приветствие с параметрами: name=Алиса, count=3
# Привет, Алиса!
# Привет, Алиса!
# Привет, Алиса!
1

Узнать «а был ли флаг указан явно» напрямую нельзя — поэтому значение по умолчанию нужно задавать всегда.

2

name, count и verbose — указатели, их нужно разыменовывать *name. При этом пакет всегда их инициализирует, так что проверка на nil не требуется.

3

flag не следует стилю GNU: -flag и --flag для него идентичны. В экосистеме Go принято использовать один дефис.

После флагов можно принимать и неименованные аргументы — список файлов, URL, что угодно, как в привычных Unix-утилитах (ls -l file1 file2, grep -n "pattern" *.txt):

main.gogo
func main() {
	var prefix = flag.String("prefix", "", "префикс для файлов")
	flag.Parse()

	files := flag.Args() // Неименованные аргументы

	if len(files) == 0 {
		fmt.Println("Не указаны файлы для обработки")
		return
	}

	fmt.Printf("Обрабатываем %d файлов:\n", len(files))
	for _, file := range files {
		fmt.Printf("- %s%s\n", *prefix, file)
	}
}
